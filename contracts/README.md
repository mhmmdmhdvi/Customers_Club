The three existing files retain 296 independent HTTP expectations: `http.json`
(107), `sessions.json` (49), and `admin-contact.json` (140). Their per-runtime exceptions document the original public
boundary decisions; Go tests consume only their Go expectations.

On 2026-10-17, before removing the Node implementation, these additional
fixtures were captured with Node 24.20.0 from product revision
`bd143dd392f1d795fd8839bfa85e9982694e87c5`:

* `backend-go/internal/admin/testdata/admin-read-node.json`: output of the
  original `backend/tests/helpers/admin-database-reference.js` for all 29 cases
  in `internal/admin/reference_test.go`. That helper calls the actual four
  Node/Prisma admin read services against a uniquely marked child created by
  testdb. Both implementations passed comparison before capture. Seed inputs
  remain in the Go regression: two users/messages/audit/security events and
  fixed January/February 2020 timestamps, pagination, invalid dates, case,
  decomposed Unicode, wildcards, escapes, injection-like text and filters.
* `backend-go/internal/session/testdata/jalaali-node.json`: `jalaali-js.jalCal`
  output `[year, march, leap]` for every year -61 through 3177 inclusive (3,239).
* `backend-go/internal/adminmfa/testdata/crypto-node.json`: original
  `createAdminMfaCrypto(Buffer.alloc(32,109)).encrypt(...)` and `generateTotp`
  output for secret `GEZDGNBVGY3TQOJQGEZDGNBVGY3TQOJQ`, time 59,000 ms. The IV
  was generated by Node and frozen with its ciphertext/tag; the six-digit code
  is independently `287082`. The Go encryption direction is also opened with
  the standard library AES-GCM API, independently of the package's decryptor.

These synthetic fixtures contain no deployed credentials or customer data.
Tests read frozen JSON; they never regenerate expected values from Go or launch
Node/npm. Keep the Jalali algorithm attribution/license beside its Go source.
